1. Sơ đồ cây Component (Component Tree)

Ứng dụng gồm 4 functional component. App là gốc, giữ state dùng chung và render 3 component con. Modal Thêm/Sửa không phải component riêng mà được render có điều kiện bên trong AddUser và ResultTable.

2. Sơ đồ luồng dữ liệu (State Lifting)

React dùng luồng dữ liệu một chiều: dữ liệu đi xuống qua props; component con muốn báo thay đổi thì gọi hàm callback mà cha truyền xuống để dữ liệu đi lên.

Diễn giải từng luồng

  1. Tìm kiếm: người dùng gõ vào SearchForm → sự kiện onChange gọi onChangeValue(e.target.value), thực chất là setKeyword của App → kw đổi, App render lại → ResultTable nhận keyword mới và chạy lại users.filter(...).
  2. Thêm: người dùng điền form và bấm Thêm trong AddUser → gọi onAdd(user) (= setNewUser) → App truyền user={newUser} xuống → useEffect([user]) trong ResultTable thêm user vào mảng users rồi gọi onAdded() để App đặt newUser về null, sẵn sàng cho lần thêm sau.
  3. Sửa / Xóa: chỉ liên quan đến dữ liệu trong bảng nên xử lý ngay trong ResultTable (state editing, users), không cần đưa lên App.

Vì sao kw và newUser đặt ở App, không đặt ở SearchForm hay AddUser?

Vì dữ liệu này được tạo ở một component nhưng lại được dùng ở một component khác cùng cấp. kw được nhập ở SearchForm nhưng được dùng để lọc ở ResultTable; newUser được tạo ở AddUser nhưng được thêm vào danh sách ở ResultTable.

Trong React, props chỉ chảy từ cha xuống con. SearchForm, AddUser và ResultTable là anh em (sibling) nên không thể truyền dữ liệu trực tiếp cho nhau. Nếu đặt kw bên trong SearchForm thì ResultTable không có cách nào đọc được nó.

Giải pháp là nâng state lên (State Lifting) tới component cha chung gần nhất — ở đây là App. App giữ state, truyền hàm cập nhật (setKeyword, setNewUser) xuống cho con nhập liệu và truyền giá trị (kw, newUser) xuống cho con hiển thị.

Lợi ích:

  • Một nguồn dữ liệu duy nhất (single source of truth): chỉ App lưu từ khóa, không có hai bản sao lệch nhau.
  • Component con đơn giản, dễ tái sử dụng: SearchForm không cần biết bảng nào dùng từ khóa của nó, chỉ cần gọi onChangeValue.
  • Luồng dữ liệu dễ theo dõi: muốn biết kw đổi ở đâu thì chỉ cần nhìn App.

Ngược lại, những state chỉ một component dùng thì giữ cục bộ: adding và dữ liệu form user chỉ nằm trong AddUser; users, loading, editing chỉ nằm trong ResultTable.

4. Lỗi gặp phải trong quá trình code và cách sửa

Error

Lỗi 1 — ReactDOM is not defined

Thông báo / hiện tượng

Trang trắng tinh, Console báo:

GET https://unpkg.com/react-%20dom@18/umd/react-dom.development.js  404 (Not Found)
Uncaught ReferenceError: ReactDOM is not defined

Nguyên nhân

Khi copy đường dẫn CDN từ file PDF, dòng react-dom.development.js bị ngắt xuống dòng thành react- + dom..., nên khi dán vào xuất hiện dấu cách trong URL. Trình duyệt không tải được thư viện ReactDOM → biến toàn cục ReactDOM không tồn tại → dòng ReactDOM.createRoot(...) báo lỗi.

Cách sửa

Gõ lại URL liền mạch và ghim phiên bản cụ thể để không bị thay đổi bất ngờ. Kiểm tra lại ở tab Network: cả 3 file đều trả về 200.

<script src="https://unpkg.com/react@18.3.1/umd/react.development.js"></script>
<script src="https://unpkg.com/react-dom@18.3.1/umd/react-dom.development.js"></script>
<script src="https://unpkg.com/@babel/standalone@7.24.7/babel.min.js"></script>
Lỗi logic

Lỗi 2 — Bấm “Thêm” nhưng form không hiện ra (nút Hủy viết sai)

Hiện tượng

Bấm nút “Thêm” không thấy modal nào mở ra, Console không có lỗi đỏ. Đặt console.log(adding) trong AddUser thì thấy giá trị in ra true rồi ngay lập tức false.

Nguyên nhân

Đoạn mã mẫu viết nút Hủy như sau:

<button onClick={setAdding(false)}>Hủy</button>

setAdding(false) có dấu ngoặc nên nó được gọi ngay khi render, chứ không phải khi bấm nút. Khi adding vừa thành true, React render form → gặp nút Hủy → gọi setAdding(false) → React render lại với adding = false → form biến mất trước khi kịp hiện. (Nếu nút này nằm ngoài điều kiện adding && thì sẽ thành vòng lặp và React báo Too many re-renders. React limits the number of renders to prevent an infinite loop.)

Cách sửa

Truyền vào onClick một hàm, để React chỉ gọi khi người dùng bấm:

<button onClick={() => setAdding(false)}>Hủy</button>
Warning

Lỗi 3 — Trùng key sau khi Xóa rồi Thêm

Thông báo / hiện tượng

Xóa user có ID 3, sau đó thêm một user mới. Bảng hiện hai dòng cùng ID 10 và Console báo:

Warning: Encountered two children with the same key, `10`. Keys should be unique
so that components maintain their identity across updates.

Sau đó bấm “Xóa” hoặc “Sửa” dòng có ID 10 thì tác động lên cả hai user, vì filter/map so sánh theo id.

Nguyên nhân

Mã mẫu sinh id mới bằng độ dài mảng:

setUsers((prev) => [...prev, { ...user, id: prev.length + 1 }]);

Ban đầu có 10 user (id 1–10). Xóa id 3 còn 9 phần tử → user mới nhận id = 9 + 1 = 10, trùng với user id 10 đang có. key trong map bị trùng nên React cảnh báo, và id trùng làm sai logic Sửa/Xóa.

Cách sửa

Lấy id lớn nhất hiện có cộng 1, nên id luôn mới dù đã xóa phần tử nào:

setUsers((prev) => {
  const maxId = prev.reduce((max, u) => Math.max(max, u.id), 0);
  return [...prev, { ...user, id: maxId + 1 }];
});

Kiểm tra lại: xóa ID 3 rồi thêm → user mới có ID 11, không còn cảnh báo.

Lưu ý

Lỗi 4 — Sửa trong form làm bảng đổi theo dù chưa bấm Lưu

Hiện tượng

Lúc đầu viết setEditing(user) và cập nhật địa chỉ bằng editing.address.city = value. Khi gõ vào ô “Thành phố” trong form Sửa, ô địa chỉ ở bảng cũng đổi theo, kể cả khi bấm Hủy.

Nguyên nhân

Object trong JavaScript được gán theo tham chiếu: editing.address và user.address trong bảng là cùng một đối tượng, nên sửa trực tiếp là sửa luôn dữ liệu gốc (mutate state).

Cách sửa

Sao chép sâu khi mở form và luôn tạo object mới khi cập nhật:

function editUser(u) {
  setEditing({ ...u, address: { ...u.address } });
}
function handleEditChange(field, value) {
  if (["street", "suite", "city"].includes(field))
    setEditing(prev => ({ ...prev, address: { ...prev.address, [field]: value } }));
  else
    setEditing(prev => ({ ...prev, [field]: value }));
}

6. Tổng kết

  • useState quản lý state; useEffect với [] để gọi API một lần, với [user] để lắng nghe user mới.
  • State Lifting: state dùng chung giữa các component anh em được đặt ở cha chung (App).
  • Controlled Components: mọi ô input lấy value từ state và cập nhật qua onChange.
  • Bất biến (immutability): thêm bằng spread, sửa bằng map, xóa bằng filter — luôn tạo mảng/đối tượng mới.
  • Luồng dữ liệu: SearchForm → App → ResultTable và AddUser → App → ResultTable.
